## The matrix and how a model is picked

`nusmp:franchise` = (index + 1) / 20, `nusmp:rarity` = (rank + 1) / 6 (common 1/6 ... mythic 5/6), `nusmp:look` 0 painted / 1 legacy. The game keeps the LAST matching override, so the file is ordered lowest priority first:
10 old franchise overrides, 55 new ones sorted by (franchise, rarity) ascending (thresholds half a step below each value), 11 legacy ones (`nusmp:look` 1; fairy_tail has no 1.82.0 cover and uses `skill_book_st_generic`).
A book without a known franchise (value 0) matches nothing and keeps the base model (the old generic grey book). The rarity comes from the stack's optional component `nusmp:skill_book_rarity` (found by id in the registry once; absent = the table), else from the table's `rarity` field, else common.

Rarity reads (same body, trim and glow differ): common iron corners and brown strap; uncommon bronze corners, green cloth band; rare silver corners and strap, blue sapphire in a bezel; epic gold, violet inlay (emissive), chain, two amethysts, glowing halo in the icon; mythic gold, ruby ringed with teal studs, chain, five horn claws arching over the top, fangs, animated glowing page edge, orange halo in the icon.

## Numbers

* Elements per body model (limit 140): common 55-58, uncommon 58-61, rare 59-62, epic 73-76, mythic 124-127. Icon models 2 elements each.
* Textures: cover 512x256 x 11, fx 288x208 x 11, trim 256x256 x 5, glow 32x256 (8 frames), icons 64x64 x 110.
* Added to the resources: models about 1.57 MB (json, compresses well), textures about 2.8 MB of PNG; the jar grows by roughly 3 MB.
* Generated by `python3 tools/lines/gen_book_textures_v2.py` (deterministic; `--check` compares decoded pixels). Preview: `python3 tools/lines/preview_book.py --matrix` (contact sheets in `build/book_preview/`) or `--model skill_book_v2_<f>_<r>.json --views z_front,z_34,fp_right,ground_20_far`.

## Server and lag (rules 9 and 11)

* Server: nothing new runs. The only server-visible code is pure (`BookLook`, `BookLookFiles`, `BookShimmerRules`, `LegacyLook`) plus the self-test, which reads the class path once. `BookLookStack` is common code and imports no client class (`ServerSafetyTest` green, no allow-list entry).
* Client item properties: two map lookups and one component read per frame per book, no allocation.
* Drop shimmer, worst case: 24 tracked item entities (collected from join / leave events, never by scanning the world), each looked at once every 6 ticks and staggered by slot, so at most 4 particles per tick (about 16 a second for 24 books), only within 24 blocks, particle options built once. Off with `dropShimmer=false`. List cleared on logout.
* Network: nothing is sent. Draw cost: at most 127 elements (about 750 quads) per mythic book in hand, 2 quads in the inventory; a ground book beyond the vanilla item distance is not drawn at all.

## What was not seen in a game

Everything was looked at in the Python previewer, which uses the game's pose maths but is not the game: real lighting, the emissive element light (`block_light` 15 on the glow and gem parts), the animated edge, the item-frame and the head slot, and the inventory tint of the plaque, ribbon and clasp gem (only simulated) are unverified. The hand pose is the same as the 1.82.0 one with a slightly larger scale (0.46 / 0.55); the owner may want to adjust it. The painted icons are rendered from the models and therefore as good as the previewer's rasteriser; the 16 px downscale in the inventory was judged on 64 px sheets. A book with no known franchise keeps the old generic grey book.
The dragons on the Exiled Heavy Knight cover are a stylised ring with heads and spines, not a copy of the reference painting; the claws of the mythic book read as a crest from the front. `BookArtAssetsTest.theFranchiseOrderMatchesTheCatalogueOfTheGenerator` needs the lead's commit 5e15ebf (fairy_tail in `lines_lib.py` / `catalog.json`) to be merged with this one.
