# Landings, Safe Zones, resting and the mod-compat processor (builder SAFE, 1.54.0)

> **1.99.0, THE HUNGER BAN.** A rest recovers health, mana and the debuffs only; it never feeds or starves: the long rest no longer resets the food exhaustion (`safe.rest_short` and `safe.rest_long` assert the food bar is exactly as it was). See `docs/labyrinth/hunger_ban.md`.


Part of the Mega-Dungeon (`docs/labyrinth/mega.md`). This builder owns four things: the **mod-compat structure processor** `nusmp:mod_compat`, the
**rest system** (short and long rests at the marked seats, hearths and beds), the **end of easy passive regeneration** outside the safe rooms, and the
**eight templates** that every sector starts and rests in (two Landings and six Safe Zones).

**State of this document.** Written without a compiler and without a game. CI compiles the Java and runs the pure JUnit tests; the templates are generated
by a script that walks them (see section 6) and are checked by `mega_check.py`; **nothing here has been run in the game** and section 10 lists exactly what
that leaves unverified. Every class and every template below says WHY it is the way it is.

## 2. The mod-compat processor

**Why it exists.** The owner wants Farmer's Delight stoves, skillets and cutting boards where the dungeon has kitchens, and MrCrayfish's Furniture Mod:
Refurbished chairs, sofas, tables, counters, crates and beds where it has furniture, **when those mods are installed**, and plain vanilla otherwise, from
ONE set of templates. A `StructureProcessor` sees every block as the sector is placed, so the swap costs nothing at runtime and nothing in the world
file, and a server without the mods gets the vanilla blocks with no configuration at all.

**How a block is chosen** (`ModCompatProcessor.processBlock`, the whole decision in about a dozen lines; a hash lookup per block):

1. `RegionContext.current()` is null (a datapack Jigsaw placing the template list outside the generator): the block is returned unchanged.
2. The compat table is empty (no compat mod loaded) or `compatEnabled` is false: unchanged. This is the common case and costs one `isEmpty()`.
3. A marker of kind `seat`, `hearth`, `bed` or `furniture` with an `as=` argument must stand in the cell ABOVE the block (for a bed head: above the bed's
   FOOT, found by turning the head's state with the placement's mirror and rotation, so both halves of a bed swap together or neither does).
4. `CompatTable.pick(hint, modLoaded, blockExists, tokens)` returns the first candidate id of that hint whose mod is loaded AND whose id exists in
   `BuiltInRegistries.BLOCK`. No candidate: unchanged.
5. The new block takes over every property of the old one that it has by name (`facing`, `half`, `part`, `lit`, `waterlogged` ...), through the
   same `BiomePaletteProcessor.carryProperties` the biome palette uses; a `facing` that must be reversed (a stair "faces" up its slope, behind the sitter;
   a chair faces the way the sitter looks) is flipped when the data says so. A mismatch never throws.

The pure half is `CompatTable` (no Minecraft types: the parsed files go in, "is this mod loaded" and "does this block exist" are predicates), unit-tested
for loaded / absent / unknown id / empty / tokens / flip / merge order. `CompatJson` parses the files with Gson and skips anything malformed;
`CompatLoader` is the reload listener (`data/<namespace>/mega/compat/*.json`, reload-safe, installs the merged table atomically) and answers
`modLoaded` through `ModList`.

**The data files** (`src/main/resources/data/nusmp/mega/compat/<mod>.json`, editable with no rebuild):

```json
{
  "mod": "farmersdelight",
  "facing_property": "facing",
  "flip_facing": ["chair", "sofa"],
  "swaps": { "stove": ["farmersdelight:stove"], "chair": ["x:chair_{wood}", "x:chair_oak"] }
}
```

* `mod` gates the whole file (`ModList.get().isLoaded`). `swaps` maps a hint to candidate ids in order of preference. `{wood}` and `{color}` tokens are
  filled from the block being replaced (`dark_oak_stairs` gives `dark_oak`; a `blue_bed` gives `blue`; defaults `oak` and `red`); a candidate whose token
  cannot be filled, or whose expansion is not a valid id, is skipped. Keys that start with `_` (like `_why`) are comments.
* `flip_facing` lists the hints whose horizontal `facing` is reversed. `facing_property` names the replacement's facing property (default `facing`).
* The hint vocabulary the templates use: `chair`, `sofa` (a stair seat), `table` (the middle slab of a trestle table), `counter`, `cutting_board` (a
  pressure plate on a counter), `skillet` (an iron trapdoor on a counter), `cooking_pot` (a cauldron beside a fire), `storage` (a barrel), `stove` (a
  campfire, furnace, smoker or blast furnace), `bed` (a bed foot). The chapel's sacred flame uses the hint `brazier`, which no file lists on purpose:
  an altar flame must never turn into a kitchen stove.

**Farmer's Delight** (`farmersdelight.json`): `stove` -> `farmersdelight:stove`, `skillet` -> `farmersdelight:skillet`, `cutting_board` ->
`farmersdelight:cutting_board`, `cooking_pot` -> `farmersdelight:cooking_pot`. These are the mod's real block ids as far as I know them, but see section 10.

**MrCrayfish's Furniture Mod: Refurbished** (`refurbished_furniture.json`): **THE IDS ARE NOT VERIFIED.** No copy of the mod was available. Every plausible
spelling is listed per hint (`chair`: `chair_{wood}`, `dining_chair_{wood}`, `stool_{wood}` ...; `sofa`: `sofa_{color}`, `couch_{color}`, `bench_{wood}` ...;
`table`, `counter`, `storage`, `bed` likewise), the first that exists in the registry is used, and when none exists the vanilla block simply stays. **To
fix it:** open the mod's jar, look in `assets/refurbished_furniture/blockstates/` for the real names, and edit the lists; no rebuild. The ids I am least
sure of are the `bed_*` family (the mod's beds may not use vanilla's `part` / `facing` pair, in which case a swapped bed would be wrong: delete the `bed`
entry, or the whole mod's bed list, if beds look broken) and `storage` (crates versus drawers versus cabinets).

## 3. Resting

**Why.** The brief: "players cannot regenerate easily; they must secure and defend Safe Zones", with D&D-style **short and long rests only when physically
using the marked seats, hearths and beds of a safe zone**. A rest is a channelled action: you use the block, you stay still and unhurt with nothing
hostile near for a while, and then you are healed and your mana comes back.

**What counts as an anchor.** A right-click on a block whose cell above holds a data marker of kind `seat` (a stair seat), `hearth` (a campfire, soul campfire,
furnace, smoker or blast furnace) or `bed` (the foot or the head of a bed) inside a Landing or Safe Zone room. The templates carry the
markers; nothing is scanned in the world (the generator saved the sector's markers; `RestAnchors` keeps a small per-sector cell index).

| Anchor | Rest | Notes |
|---|---|---|
| seat, hearth | SHORT, 10 s, heals 40 % of max health and 40 % of max mana, costs one of 3 short rests | `shortRestSeconds`, `shortRestHealth`, `shortRestMana`, `shortRestUses` |
| bed | LONG, 30 s, heals everything, refills mana, aura and the short rests, lifts exhaustion debuffs | at most once per 6000 ticks (5 minutes), `longRestCooldownTicks` |

**Refusals** (`RestRules.checkStart`, in this order; each one tells the player why on the action bar): rests disabled; creative or spectator (the click
passes: vanilla carries on); a rest already under way (a second click is swallowed silently); not in a safe room; the player is more than 3.5 blocks
from the clicked block; a hostile mob within `hostileRadius` (16) blocks; no short rests left; a long rest too soon after the last.

**Interruptions** (`RestRules.checkChannel`, every 10 ticks, and damage at once): the player was hurt, moved more than 1.5 blocks from where they sat
down, left the safe room, a hostile came within 16 blocks, died or left the dimension. The rest ends with a message and costs nothing.

**Completion.** `player.heal`, then mana through the SAME calls the grimoire books use (section 7), `lastRest`, the quest key `mega.rested` with the argument
`short` or `long`, and for a long rest: every short rest back, the cool-down starts, the fatigue effects (darkness, weakness, slowness, mining fatigue,
hunger, nausea, blindness) and the exhaustion are lifted, and the player's persistent int `nusmp_mega_landing` is raised to this sector's id when higher
(the dungeon respawn Landing the generator's travel code reads). The Gloom clock needs no reset call: `DungeonHunger` keeps it in a private map with no
public reset and no saved keys, and it falls two a second wherever there is light (the floors of the safe rooms are lit to at least 6, above its dark
limit), so a rest of ten or thirty seconds empties it by itself; what a rest lifts are the effects the clock had applied.

**The ambush.** A long rest rolls `min(ambushMaxChance, ambushChance x sector threat)` (default 5 % per threat level, at most 50 %); when it hits, the
ambush is announced between a quarter and three quarters of the way through to every registered `RestAmbushListener` (`SafeRegistry.addAmbushListener`);
**this builder spawns nothing**: the Encounter Director may register a listener and turn the announcement into monsters. With no listener nothing happens.

**Choices worth knowing.**

* **Beds in this dimension explode in vanilla.** The Mega-Dungeon's dimension type has `bed_works = false`, and vanilla blows up a bed that is right-clicked
  there, in the player's face. Since beds are rest anchors, every right-click on a bed in the dimension is taken here (`protectBeds`, default on): a marked
  bed starts a long rest, any other bed refuses politely, so no decorative bed of any template can hurt a player.
* **Furnaces keep their menus.** A furnace, smoker or blast furnace that is a hearth marker opens its menu on a plain click (cooking is what it is for);
  to rest at one the player sneaks and clicks. Campfires, seats, beds and the Farmer's Delight stove have no menu, so a plain empty-hand click rests;
  food in the hand on a hearth is left to the campfire or the stove (it cooks).
* **Sneaking with an item** in the hand is left alone (that is "place a block").
* **Never throws out of a handler.** A failed rest is logged and ends; a quest hook that throws cannot undo a rest; a player Tensura does not track
  (no storage yet) loses the mana part of the rest only.

**Classes.** `RestKind` (SHORT / LONG), `RestRules` (every rule and number, pure), `RestState` (the attachment: used short rests, last long rest, last rest;
the channel is transient), `RestAnchors` (marker lookup per sector), `RestMana` (the mana calls), `RestEvents` (the handlers and the three PUBLIC entry
points `interact`, `advance`, `interruptByDamage`, which take the game time as an argument so the self-tests can run a ten-second rest in microseconds),
`RestAmbushListener`, `SafeCommand` (admin), `SafeRegistry` (registration), `SafeConfig`, `SafeSelfTests`.

**Admin command** (`SafeRegistry.command()`, attached by the lead under `/multiverse mega`, permission 2): `rest status [player]` (short rests left, the
long-rest cool-down, the rest in progress, the sector and whether the player is in a safe room, whether the regeneration throttle is on, the mana share and
which compat hints are live), `rest refill <player>` (every short rest back, the cool-down cleared, any rest ended), `rest anchors` (how many seat, hearth and
bed markers the sector at your feet has, how many are in this room and the nearest of each: the quickest check that a template's markers arrived).

## 4. No easy passive regeneration

**Why.** "Players cannot passively regenerate health or mana easily." In the Mega-Dungeon, **outside** a Landing or Safe Zone, natural regeneration is
multiplied by `passiveRegenScale` (default **0.25**, 1 = vanilla, 0 = none). **Inside** a Landing or Safe Zone regeneration is normal, so a safe room is a
place to catch your breath even before you rest. Creative and spectator players are exempt.

* **Health** goes through `LivingHealEvent` (`RegenThrottle.onHeal`, the pure rule is `RegenMath.scaleHeal`). **This is a heuristic, and says so:** vanilla's
  natural regeneration (`FoodData`) heals in steps of at most one point (`heal(1.0f)`, or `saturation / 6`), so a heal of 1.0 or less on a player without the
  Regeneration effect is treated as natural and scaled; a result under 0.005 is cancelled. Bigger heals (potions, spells, food, rests) are not touched, and
  the Regeneration effect is exempt. A mod that heals a player by a tiny amount for another reason is scaled too; there is no way to tell them apart.
* **Magicule and aura** cannot be intercepted that way, so a **transient attribute modifier** (`ADD_MULTIPLIED_TOTAL`, amount `scale - 1`, the fixed ids
  `nusmp:mega_regen_magicule` and `nusmp:mega_regen_aura`) goes on Tensura's `MAGICULE_REGENERATION_MULTIPLIER` and `AURA_REGENERATION_MULTIPLIER` while the
  player is in the dimension outside a safe room, and comes off when they enter one, leave the dimension or the config changes. A transient modifier is not
  saved, so a crash or a logout can never leave a player throttled in the Overworld. The check runs once a second per player.

## 5. Config (`nusmp-labyrinth-mega-safe-server.toml`, section `[safe]`)

Plain `define` / `defineInRange` only, every reader goes through `SafeConfig.get`, which answers the default while the spec is not loaded (the processor runs
during world generation, before SERVER configs are read).

| Key | Default | Range | Meaning |
|---|---|---|---|
| `restEnabled` | true | | rests on or off (the beds still never explode) |
| `shortRestSeconds` | 10 | 1..120 | length of a short rest |
| `longRestSeconds` | 30 | 1..600 | length of a long rest |
| `shortRestUses` | 3 | 1..9 | short rests between two long rests |
| `shortRestHealth` | 0.4 | 0..1 | share of max health a short rest restores |
| `shortRestMana` | 0.4 | 0..1 | share of max mana a short rest restores |
| `restAura` | true | | a rest restores aura as well as magicule |
| `longRestCooldownTicks` | 6000 | 0..1728000 | ticks between two long rests of one player |
| `hostileRadius` | 16.0 | 1..64 | a hostile this close forbids and breaks a rest |
| `ambushChance` | 0.05 | 0..1 | chance per level of sector threat that a long rest brings an ambush |
| `ambushMaxChance` | 0.5 | 0..1 | the ceiling of that chance |
| `passiveRegenScale` | 0.25 | 0..1 | regeneration outside safe rooms (1 vanilla, 0 none) |
| `protectBeds` | true | | no bed explodes in the dimension; marked beds rest, others refuse |
| `compatEnabled` | true | | the compat processor may swap blocks |

Both Landings also carry an **exit gate** (a 3 x 3 plane of `nusmp:labyrinth_exit` in a framed alcove with a sign, the way home) and one `arrival` marker three
blocks in front of it. Every door of every room has a **raised portcullis** (iron bars above the lintel in the inner wall layer, a chiselled keystone) so it
reads as a door you could bar. The chapel's windows are glass in the outer wall layer with an invisible `light` block hiding in the carved slit, which is what
makes the coloured glass glow. Furnaces, smokers and blast furnaces are authored **lit** so the forge and the kitchens glow, but the verifier does **not** count them as
light: whether a furnace with no fuel in it stays lit is the game's business and was not seen (so the rooms must be, and are, bright without them; campfires,
soul campfires, lanterns, candles and lava cauldrons are stable and do count).

**The generator and its verifier.** `python3 tools/labyrinth/gen_mega_safe.py` builds all eight (the same bytes every run), **verifies each one and refuses to
write a template that fails**, `--check` writes nothing, `--render DIR` draws every room (four isometric views, a plan with the markers, a block-light map).
The library `mega_safe_lib.py` (a room builder `SR` that places a block and its marker in one call, wall-relative coordinates `Wall`, architecture, lights,
furniture), the three room modules (`mega_safe_landing.py`, `mega_safe_halls.py`, `mega_safe_shops.py`) and `mega_safe_verify.py` are this builder's own;
`mega_lib.py` is the shared toolkit and is not edited. The verifier is a conservative model of a person walking: 4-neighbour movement, 2-high clearance, a
step of one block only onto a stair, slab or bed, ladders, drops of at most 3. It checks:

1. the **shell** is closed (floor, ceiling, outer wall layer, except the doorways);
2. every **door** has a clear 3 x 4 x 3 approach and every door can be walked to from every other;
3. every **seat, bed, hearth, patrol point and the arrival cell** can be reached on foot (a standing cell within 2, hearths within 3);
4. **light**: the block light on every walkable floor cell is at least 6 (the Gloom clock counts 4 or less as dark) and at least 8 at seats, beds and hearths,
   computed by a flood fill that is optimistic through partial blocks;
5. **support**: no chain, hanging lantern, wall torch, banner, ladder, floor candle, carpet or door half hangs from or stands on nothing;
6. **markers**: a seat marker is above a stair and has a `facing`, a bed marker is above a bed FOOT, a hearth marker above a fire, every `as=` hint is present,
   no marker was overwritten by a later block, none of the forbidden kinds (spawn, faction, trap, pedestal ...) appears, only a Landing has an `arrival`;
7. **counts**: seats, hearths, beds (1 to 3), patrol markers (1 or 2), armour stands, file size.

It found real mistakes while the rooms were written: a balcony nobody could climb to (the stair was one block short), lanterns hanging at head height over the
only corridor of a gallery, a marker buried under a lamp, chains that ended in air, a door whose approach a pilaster blocked. Run it before trusting a
change. After a change run `mega_check.py` (only "pool nusmp:mega/side does not exist" and "not referenced by any pool" may remain for these rooms until the
pools exist) and `mega_catalog.py`.

## 7. How mana and the Tensura attributes are used, and how that was checked

Nothing here could be run, so every call was checked against the API dumps of the Tensura Reincarnated jar the mod builds against (the same dumps the
grimoire books were written from):

* **Mana** is Tensura's magicule (aura is the second pool): `TensuraStorages.getExistenceFrom(player)` gives the existence storage; `getMagicule()` /
  `setMagicule(double)` / `getAura()` / `setAura(double)` / `markDirty()` on it, and `EnergyHelper.getMaxMagicule(player)` / `getMaxAura(player)` for the
  maximum. These are the calls `KotodamaWords.pay` and `avatar.TensuraBridge.refundMagicule` already make. A rest sets the value directly (`min(max, now +
  max x share)`) instead of calling `EnergyHelper.gainMagicule`, on purpose: that path applies Tensura's gain multipliers, so a "40 % rest" would give 44 %
  to a player with a +10 % gain skill. A rest is a rule, not a gain.
* **Attributes**: `TensuraAttributes.MAGICULE_REGENERATION_MULTIPLIER` and `TensuraAttributes.AURA_REGENERATION_MULTIPLIER` (both `Holder<Attribute>` in
  `io.github.manasmods.tensura.registry.attribute`), used through `Player.getAttribute(holder)`, `AttributeInstance.addOrUpdateTransientModifier`,
  `getModifier(ResourceLocation)` and `removeModifier(ResourceLocation)` with `AttributeModifier(ResourceLocation, double, Operation)` (the 1.21 signature).
* What the dumps cannot say is the **runtime semantics** of the two multiplier attributes: that they are read as a multiplier of the per-tick regeneration
  (`ADD_MULTIPLIED_TOTAL` with `scale - 1` is the standard way to scale a multiplier, but if Tensura reads them as an additive bonus the throttle would do
  nothing, never harm). The self-test `safe.regen_throttle` checks that the modifier is put on and taken off; only the game can show the effect.

`safe.processor_list` needs `nusmp:mod_compat` in the processor list `nusmp:mega_interior`.

## 10. What is NOT verified (honest list)

1. **Nothing ran in the game.** No rest, no throttle, no swap, no template placement has been seen working. The pure rules are unit-tested and the in-game
   self-tests are written to be run by CI's smoke test; they have never been run.
2. **No compiler saw the Java.** It was type-checked against partial stubs of the Minecraft, NeoForge and Tensura APIs: what remains are errors about
   missing stubs (the data attachment methods, `BlockPos` as an abstract class, `Registries.STRUCTURE_PROCESSOR`, a few registry constants), the same errors
   existing code in the repository produces under the same stubs. Every API signature was looked up in the dumps; the places where that proves less are
   listed in the report (the processor type registry key, `AddReloadListenerEvent.addListener`, the `FakePlayer` behaviour in the self-tests).
3. **The Refurbished Furniture ids** (section 2) and, to a lesser degree, the four Farmer's Delight ids.
4. **The runtime meaning of Tensura's regeneration multipliers** and the heal heuristic (section 4): a mod that heals in tiny steps is throttled too.
5. **The templates were verified by a model of walking and by renders, not by a person.** Light is a flood-fill estimate, not the game's. Whether a room
   looks good is the owner's call; the renders are in `gen_mega_safe.py --render`. The chapel's glowing windows depend on the game lighting the front face of
   the glass from the hidden light block, which is the vanilla behaviour but was not seen. The `minecraft:potted_azalea_bush` pot was left out because its
