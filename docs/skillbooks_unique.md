# Skill Books teach Unique skills (1.96.0)

The owner's request (verbatim): "remove all the fairy tail magics from the skill books system, also change the skill book system to make it so when you use one you get the unique skill and just remove the skill
tree system". This document is the binding description of what exists now. The old Skill Tree design is gone (see `docs/skilltree/REMOVED.md`).

## 0. New versus replacement (CLAUDE.md rule 5)

| Part | Status |
|---|---|

## 1. What a book does

* One item, `nusmp:skill_book`, the data component `nusmp:skill_book_id` says which book (`nusmp:lady_luck_book`). Name, cover colour, lore and the franchise cover come from the shipped table
  `assets/nusmp/skill_books.json` (generated by `tools/lines/gen_book_index.py` from the route files), so a book looks right on both sides with no data pack.
* Right click (server): the book teaches the unique skill of that book, switched ON, shows the unlock banner and effect, and is used up (a creative or admin reader keeps it). If the reader already owns the skill
  the book stays closed and a message says so. Decisions are in the pure `item/BookRules`, the carrying out in `item/BookUse`; the skill is taught first and the stack shrunk only if that worked.
* An old book of a removed magic, or an old SP Book (`nusmp:sp_book`, kept registered with its components), is not blank: reading it turns it into a random book the reader does not own yet.
* Where the books come from: the Mega-Dungeon loot modifier `nusmp:skill_books` (monsters, Guardian), the rift chests' modifier `nusmp:rift_books`, the Black Market (the all-books line and the flagship Smoldering
  Fang), the creative tab (one per skill) and `/multiverse skillbook give`. The SP Books are gone from all of them (a plan's SP count is ignored; the old `sp_book` stock lines make no slot). The drop and the shop
  only hand out a book whose unique skill exists (`LineIndex.known`).

## 2. The unique skill (`skilltree/unique/LineUniqueSkill`)

* A Tensura `Skill` of type UNIQUE, registered at mod construction from the shipped table by `UniqueSkills` (a separate `DeferredRegister`, filled in id order, so the registry is identical on every machine). 254
  skills, ids `nusmp:line_<id>`, name and description through `nusmp.skill.line_<id>` (+ `.description`) with English fallbacks built by `SkillTexts`. It appears in Tensura's own Ability Selection screen like any
  Unique skill; nothing of ours is drawn on top of it.
* **Active:** the modes are the line's arts in route-file order (the first is the signature art); scroll to change, press the skill key to cast. The cast goes through the existing engine: `LineCast` (the magicule
  price through `AbilityKit.pay`, the target check, the executor, the balance law, the cooldown) for generated lines, or the technique class (`TechniqueSkill.castDirect`) for the four Heavy Knight books. A cast
  earns a point of mastery. The cooldown is shown on the mode name. An art that cannot find a target says so and costs nothing.
* **Passive:** while the skill is switched ON (Tensura's own toggle; it is on when learned) the line's passives and stat bonuses act, through the unchanged `LinePassives` / `PassiveExecutors` / `LineAttrs` /
  `LineStances` paths and the single gate `LineGate`. Switched off, nothing acts. Several owned skills can be on at once (the old "one equipped line" rule left with the Skill Tree).
* **Mastery** (Tensura's own, 0 to 100 percent of the instance maximum) replaces the SP levels: every art cast and every ten seconds the skill is on adds a point. `MasteryLevels`: a node counts at level
  `1 + floor(mastery * maxLevel)`, capped at its maximum; art number `k` of `n` awakens at `k/n` mastery (the signature art needs none). Pure and unit tested.
* An art that cannot be reproduced gets no special generic strike: every art of the 254 files has a catalogue kind with an executor (`LineKindsTest` pins that), and the four Heavy Knight books run their own
  technique classes, so no fallback strike was needed.

## 3. Migration (`unique/LegacyMigration`, `MigrationPlan`)

At login and respawn, for a player whose old Skill Tree record still holds anything (lines, Skill Points, node levels, equipped line, switches): every owned line that still exists is taught as its unique skill,
switched on (a player who held the 1.92 inert stand-in of that line gets it switched on); lines of removed magics and unknown or foreign-namespace ids are dropped; then Skill Points, spent points, node levels, the
equipped line and the switches are cleared (only when every grant went through, so a refusal is retried at the next login). The Black Market gold lives in the same record (`extra("market")`) and is never touched; the
attachment `nusmp:skill_tree` stays registered for that. Every login also forgets the inert stubs of the removed magics and the old technique skills (`hk_*`, `ft_*`), which can no longer be used. Nothing crashes
on an old record: every step is guarded.

## 4. Kept for old saves (inert)

* Skill registry ids: the 30 `nusmp:ft_*` technique skills and the 29 `nusmp:line_<removed>` skills are registered as `LegacySkill` stubs (cannot be used, toggled, slotted). Their ids are in `unique/LegacyIds`
  only; no data, lang, loot or shop file names them (`UniqueBooksFilesTest`).
* Items and components: `nusmp:sp_book`, `nusmp:sp_amount`, `nusmp:sp_kind`, `nusmp:skill_book_id`.
* The `hk_*` technique skills stay registered (the Heavy Knight books run them as modes) but can no longer be learned or used on their own.

## 5. Commands and config

`/multiverse skillbook list | learn <player> <line> | forget <player> <line> | give <player> <line> | gold <player> [add|set <n>] | shop status|stock|restock` (permission 2). `gold` and `shop` moved here from the
removed `/multiverse tree`. Configs: the tree config file `nusmp-skilltree-server.toml` is gone; `nusmp-skilltree-loot-server.toml` and `nusmp-skilltree-shop-server.toml` stay (file names unchanged so a server
keeps its settings). The Tensura menu config `nusmp-tensura-menu-common.toml` is gone. No keybinds, packets (except the unlock banner and the shop's) or advancements of the tree remain.

## 6. Files

* Code: `skilltree/unique/**` (the skill, the registry, the use logic, the migration, the events, the command, the self-test), `skilltree/item/**`, `skilltree/loot/**`, `skilltree/shop/**`, `skilltree/line/**`
  (engine), `skilltree/hk/**`, `skilltree/kit/**` (the effect clock, world helpers and allies helper that the engine shares; formerly `ft/kit` with an `Ft` prefix), `skilltree/state/**` (the legacy record),
  `skilltree/data/**` (the line loader and schema, unchanged), `client/skilltree/{SkillBookClient, ItemsClient, BookClient, ShopClient, BannerTimeline, shop/**}`. The package name `skilltree` stays so the Hub
  economy and the Mega-Dungeon loot keep their imports.
* Data: `data/nusmp/skill_trees/*.json` (254), `assets/nusmp/skill_books.json` (the table), `data/nusmp/black_market/*`, `data/nusmp/loot_modifiers/*`.
* Tools: `tools/lines/*` (rows, catalogue, book index, 3D book covers), `tools/skillbooks/gen_unique_books.py` (writes `tools/lang/skillbooks_unique.json` and `tools/lang/skillbooks_unique.remove.txt`),
  `tools/tensura_menu/gen_line_icons.py` (the 32 by 32 skill icons), `tools/skilltree/gen_item_icons.py` (the book sprite) and the shop art tools.
* Lang: the flat fragment `tools/lang/skillbooks_unique.json` is for the lead to merge; `tools/lang/skillbooks_unique.remove.txt` lists the stale `en_us.json` keys of the removed systems to delete. The game
  reads everything with a fallback, so nothing shows a raw key before the merge. New keys were used wherever a text changed (`msg.nusmp.line.not_awake`, `tooltip.nusmp.skill_book.owned`,
  `item.nusmp.sp_book.faded`).

## 7. Tests

JUnit: `BookRulesTest` (grant, refuse a duplicate, creative keeps the book, the swap), `MigrationPlanTest`, `MasteryLevelsTest`, `LineIndexTest`, `LegacyIdsTest`, `SkillTextsTest`, `UniqueBooksFilesTest` (no removed
id in the data, the shop, the loot, the table or the lang fragment; every book has a data file, a skill id, an icon and lang entries), `SkillBookLangTest` (every literal fallback of the books is in the fragment),
`LineAssetsTest` (the table agrees with every route file, including the modes), plus the kept tests of the data, loot, shop and gate. In game: `skillbook.unique` (the registry, the data against the table, and a
stand-in player that reads, is refused, reads as a creative player and swaps an old book), `skillbook.loot`, `skillbook.shop.stock`, `skillbook.shop.buy`.

## 8. Adding a book

Add a route file (rows under `tools/lines/rows/` and `tools/lines/gen_lines.py`, or a hand-written file), run `python3 -B tools/lines/gen_book_index.py`, `python3 -B tools/tensura_menu/gen_line_icons.py` and
`python3 -B tools/skillbooks/gen_unique_books.py`. The skill is registered from the table at start-up; a data pack can retune an existing line's numbers but cannot add a skill (the registry freezes).

## 9. Not verified

Nothing was run in a game or a Gradle build in this environment (type-check against API stubs and the pure JUnit tests only). Not seen in a running game: Tensura's Ability Selection screen showing the 254 skills and
their mode names, the toggle control and the key press coexisting on one skill (the Grimoire books and the Legion book do the same, so it is expected to work), the login migration on a real old save, the
registry sync of the new skill ids between a dedicated server and a client, the mastery progression feel, and the Black Market and rift loot after the change. The balance of giving every art of a line without
Skill Points is gated only by mastery awakening; the numbers were not retuned.
